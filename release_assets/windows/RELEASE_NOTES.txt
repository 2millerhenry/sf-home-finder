SF Home Finder 0.5.9 for Windows x64

The install now says how far along it is, not just how long it has been
going. The step that takes the longest -- the one that gets everything ready
before the app starts -- counts its way to a hundred per cent as it loads,
which is a real count of the work rather than a bar moving on a timer.

A neighbourhood you have chosen is removed with a cross rather than the word
"Remove" beside every one of them, the note under the budgets is shorter, and
the shortlist no longer carries a sentence about how unpriced homes are
placed.


SF Home Finder 0.5.8 for Windows x64

Installing says what it is doing. Each step is one line with a tick and the
time it took, instead of forty-seven library names scrolling past, and the
line you are waiting on is the only one moving.

Upgrading no longer looks like it failed. A first start after an install
re-ranks every home already collected, and macOS vets a runtime it has never
seen, and nothing is served until both finish. On a real board of 9,615 homes
that took fifty seconds run plainly and seventy-three inside the background
service the app runs as -- six minutes on a machine still busy installing.
Past two and a half minutes the installer gave up and said it had not worked,
while it was working. That work now happens during the install, as one
visible step that nothing throttles, and the app itself then starts in three
and a half seconds.

A slow first start used to fail the install outright and send you to Repair
for an app that was starting normally. The work that made it slow is done
during the install now.


SF Home Finder 0.5.7 for Windows x64

Your data is much harder to lose. Mac and Windows now keep backups by one
set of rules. Repair restores the newest copy that opens cleanly and never
deletes the last one, and a board that is damaged is refused at start with a
message that says to run Repair, rather than a page that half works. This
matters most on the way up from an older version: Repair up to 0.5.6 deleted
the backups it was meant to restore from and restored nothing. This release's
Repair runs its own script, not the one an older install left behind.

The same home listed on several sites now appears once. Copies are joined only
on clear evidence, because merging two different flats would hide one of them;
a star or a pass reaches every copy, and the counts beside your cut-off count
homes rather than listings. Where a site states no rent, the typical rent of
homes the same size in the same neighbourhood is used to rank it, and is never
shown as though it were the asking price.

The sites are asked less, and more gently. A check refused partway keeps the
pages it had already read, errors are said in words, a site your deal does not
need is not asked at all, and a check that ran with no network no longer
counts against a source as though the source had failed.

It stays quick after a year of use. Measured on a board of 213,000 homes: the
dashboard opens in under half a second instead of nearly six, starting takes
3.3 seconds instead of 4.6, and a page of the archive about a second instead
of twenty. A home stays on the board for 21 days after it is found, then moves
to the archive; once no site lists it any more it is kept for 120 days and
then cleared -- except any you starred, noted or passed, which are never
cleared.

The neighbourhood filter no longer lists "San Francisco" as though it were a
neighbourhood beside Castro and Nob Hill.

The installer names each of its four steps instead of sitting on one unchanging
line while it fetches a private Python and the libraries it needs.


SF Home Finder 0.5.6 for Windows x64

Checks finish about forty seconds sooner. Sites that answer only for themselves -- the city's own
portal, Zumper, Uloop, AvalonBay, SpareRoom, Movoto and the building managers
-- are now read on a second line beside the two companies that count their
requests together (Zillow, Trulia and HotPads; Rent.com, ApartmentGuide and
Apartments.com), which stay strictly in turn. No site is asked for two things
at once or read any faster than before. SF_HOUSING_SEQUENTIAL_SCAN=1 puts
everything back in one line.

The rest of this release is a fix to the Mac's terminal command, which
Windows does not have: here the shortcuts in the folder you unpacked are the
way in.

Near matches means near. It used to hold everything that was not on the
shortlist; it now holds homes that missed by one thing -- a few points short
of your cut-off, or a little over your budget -- and each row says which, in
money, with the nearest miss at the top. Everything else collected is still in the full archive.

The Say thanks panel is tidier: the right size for what it shows, readable in
either theme, it says when it is loading, and it always offers a plain link to
Ko-fi in a browser tab in case their page will not draw inside the panel.

SF Home Finder 0.5.5 for Windows x64

Near matches means near. It used to hold every home that was not on the
shortlist, which on a real board meant 7,785 homes -- 7,625 of which the deal
had ruled out outright, for the wrong number of bedrooms or twice the budget.
It now holds only the homes that came within ten points of your cut-off.
Nothing is hidden; everything collected is still in the full archive.

Installing downloads about six megabytes less and installs ten fewer packages:
the app was asking for a bundle of extras it never used.

SF Home Finder 0.5.4 for Windows x64

Checking for new homes takes less time, the very first check included.
Craigslist runs on its own servers, so it is now read alongside the other
sources instead of ahead of them, and a check is shorter by about as long as
Craigslist takes. No site is asked for anything more than before: each is
still read one page at a time, and every other source is read in the same
order and at the same pace. SF_HOUSING_SEQUENTIAL_SCAN=1 puts every source back
in one line exactly as it was.

SF Home Finder 0.5.3 for Windows x64

Upgrading could fail part way through. Installing over a copy that is already
running means replacing files that copy has open, and Windows will not delete
an open file. The installer asked the app to stop, waited two seconds and
started anyway, which is usually enough and therefore fails exactly on the
slow and busy machines where an upgrade takes longest. Repair went through the
same path and could fail the same way. It now waits for the old copy to let
go, insists if it will not, and retries.

Everything else is as it was in 0.5.2, which was the first Windows build since
0.3.9. If you are coming from that one, read on.

SF Home Finder 0.5.2 for Windows x64

The first Windows build since 0.3.9. Everything below happened in between,
and all of it is new if you are coming from that one.

Start here: the 0.3.9 installer had been looking for a file that stopped
being built shortly afterwards, so a Windows install has not actually
worked for a long time. It does now, and it is checked on a real Windows
machine every time anything changes rather than read over on a Mac. Doing
that turned up three more faults, all fixed here: the installer gave up
waiting after 45 seconds when a first start can honestly take longer,
uninstalling failed part way through with a permission error because it
began deleting the app before the app had finished stopping, and opening
your browser at the end could fail an install that had otherwise worked.

It is called SF Home Finder now. The app always called itself that while
the download said SF Housing Monitor. Your data folder and the sign-in task
keep their old names on purpose, so nothing is orphaned.

It can tell you when a newer version exists. A line appears in small print
at the bottom of the app, and getting it is the same as installing it:
download the new release and run Install again, which keeps your deal, your
homes and your notes. The app asks GitHub once a day whether a newer
version exists and sends nothing about you, not even which version you are
running. SF_HOUSING_NO_UPDATE_CHECK=1 stops it entirely.

The number beside the match slider is right in three places it was wrong.
Raising your budget could not raise it. People splitting a home were shown
a fraction of what is there, because the rent each person pays was read as
the rent for the whole place. Naming neighborhoods made no difference at
all. Before you have searched anything it now estimates what a search like
yours usually finds instead of sitting at nothing.

Homes that have been taken down leave the shortlist promptly, and checking
by hand is limited to once a day so that no source stops answering you.

One thing macOS has that this does not: a homefinder command for the
terminal. Here the Install, Open, Repair, Verify and Uninstall shortcuts in
this folder are the way in, and Open is the one you will use.

SF Home Finder 0.3.9 for Windows x64

This Windows release uses the same local-only SF Home Finder application as
the macOS release. A blank install contains no housing profile, listings,
credentials, tokens, or personal paths.

The installer runs only for the signed-in Windows user. It downloads a private
Python 3.12 runtime, creates an app-owned environment under LocalAppData, and
starts the local dashboard at http://127.0.0.1:8000. It creates a normal user
sign-in task so scheduled checks can continue after the browser closes.

No optional connector blocks the account-free public-source workflow. Gmail is
read-only and needs an owner Google OAuth client plus real saved-search alerts
before individual providers are called working. Furnished Finder needs Chrome.
Facebook automation needs an optional Apify token and supports only the public
coverage described in Sources.

The ZIP is unsigned. Keep it private and only run a copy supplied by the owner.
